# Google Ads skills library (eppc edition) — design

Date: 2026-09-03. Status: approved by the owner in chat.

## 1. Goal

Turn the raw harvest of 145 TrueClicks Google Ads audit skills in this folder into a curated, versioned, EU-ready skill library that a Claude agent can run directly against a client's Google Ads export. The work happens only inside `google-ads-skills-eppc/`. No TypeScript engine, no changes to `studio/` or client repos.

The council verdict of 2026-09-03 (transcript in the session scratchpad) drives the scope: provenance, classification, deduplication, parametric thresholds in account currency, localized output with per-finding provenance, a rewritten front desk, and minimal governance rules.

## 2. Non-goals (documented in README as out of scope)

- Live Google Ads API client; any executable engine.
- A data-processing agreement (DPA) with TrueClicks; the library only states the rule.
- Running a real account through the skills (the owner does this later with a manual UI export).
- Filling the 17 missing upstream numbers or adding Microsoft Ads skills.
- Validating every reference GAQL query against the current API version (recorded as `gaql_verified: null`).
- The orphan file `~/.claude/skills/SKILL.md` (outside this folder).

## 4. Per-skill frontmatter

Every `skills/*/SKILL.md` starts with:

```yaml
---
name: skill-121-impression-share-loss-analysis
description: "One line."
allowed-tools: Read, Grep, Glob
metadata:
  library: eppc-ads-skills@1.0.0
  upstream: trueclicks/claude-plugins google-ads@1.8.0
  upstream_skill: skill-121-impression-share-lost-analysis   # exact upstream name
  category: competitive          # from the schema's category table (section 5)
  kind: deterministic            # deterministic | analyst | operational
  data_source: custom_gaql       # standard | custom_gaql | external
  merged_from: [skill-133-impression-share-loss-analysis]   # only when applicable
  related: [skill-135-top-of-page-rate-monitoring]           # optional
  markets: all                   # all | us_only | eea_relevant
  gaql_verified: null            # API version the queries were checked against, or null
  reviewed: 2026-09-03
---
```

`name` keeps the upstream number and slug, and every skill directory is renamed to that full name (`skill-NNN-slug`, as in the upstream plugin), except where a merge renames the canonical (section 6). `allowed-tools` is unchanged. The body keeps the five sections in order: `## Purpose`, `## Data Requirements`, `## Analysis Steps`, `## Thresholds`, `## Output`. The schema doc is updated to say `## Output` (the files already do); no body headings are renamed.

The broken command reference `/google-ads-get-custom` is restored to `/google-ads:get-custom` everywhere (upstream's real command).

## 5. Classification rules

`category` comes from the upstream schema table by number range: 001-011 structure, 012-024 keywords, 025-038 creative, 039-052 bidding, 053-063 targeting, 064-069 quality, 070-081 tracking, 082-095 shopping_pmax, 098-112 remarketing, 113-129 waste, 130-138 competitive, 139-145 compliance, 146-152 seasonal, 153-162 platform.

`data_source` maps the existing "Data Source" line: `Standard` → standard; `Custom GAQL Required` and `Standard + Custom GAQL` → custom_gaql; any variant mentioning external data, external testing, Merchant Center, account configuration review, or "for comparison" → external. The nine non-standard strings are rewritten to one of the three canonical values.

`kind` is decided per skill by this rule, in order:

1. **operational** if the deliverable is something to deploy or schedule rather than a finding: automated rules, scripts, alert configuration, scheduling, countdown customizers, pre-launch checklist. Initial list: 049, 122, 123, 124, 125, 130, 145, 146, 147, 149.
2. **analyst** if `data_source: external`, or the thresholds cannot be computed from Google Ads data alone (needs CRM, site testing, business goals, judgment about intent or naming). Initial list: 003, 011, 024, 034, 038, 069, 071, 074, 078, 079, 080, 081, 106, 141, 152, 156, 161, plus any skill whose thresholds table has no numeric condition.
3. **deterministic** otherwise.

The final assignment is recorded in `CATALOG.md`; the plan includes a review step where the full table is shown before committing.

`markets`: 058 gets `us_only` for its household-income section (body note: unavailable outside the US, skip for EU accounts). 075 (Consent Mode v2), 156 (first-party data) and 072/073 (enhanced conversions) get `eea_relevant`. Everything else `all`.

## 6. Merges

Eight merges, chosen because both skills check the same condition on the same data. Canonical keeps its directory and number; the absorbed directory is deleted with `git rm`; the canonical's frontmatter lists `merged_from`; `skills/MERGES.md` records each merge.

| 121 impression-share-lost-analysis | 133 impression-share-loss-analysis | skill-121-impression-share-loss-analysis |
| 023 close-variant-broad-match-monitoring | 120 close-variant-match-expansion-monitoring | skill-023-close-variant-query-expansion-monitoring |
| 061 customer-match-list-freshness | 104 customer-match-list-management | skill-061-customer-match-list-health |

| 029 rsa-asset-performance-analysis | 126 rsa-asset-performance-bulk-analysis | skill-029-rsa-asset-performance-analysis |

Where the canonical is renamed, the directory is renamed too (`git mv`), and `upstream_skill` keeps the original upstream name.

Merge procedure for each pair:

- **description / Purpose:** rewritten in 2-3 sentences covering both scopes.
- **Data Requirements:** keep the canonical's data source and GAQL; append the absorbed GAQL only when it selects fields the canonical lacks. `data_source` becomes the broader of the two (custom_gaql beats standard).
- **Analysis Steps:** union, deduplicated, at most 6.
- **Thresholds:** union, deduplicated, at most 8 rows. When both define the same condition with different severity, keep the stricter severity and note it in MERGES.md. Money literals are parametrized per section 7 during the same edit.
- **Output:** canonical's template, extended only if the absorbed skill reported an entity the canonical did not.
- **129's** "recommend automated alerts" step survives as one operational step inside 064, not as a separate skill.

Pairs reviewed and deliberately not merged (linked with `related` instead): 044/123 (monthly pacing vs day-of-week allocation), 013/014/127 (keyword mining, negative mining, trend detection), the conversion-tracking cluster (070, 071, 107, 108, 110, 081), the landing-page cluster (034, 069, 078, 079, 125, 141), and 065/066/067 (Quality Score components and trend).

Result: 137 skills.

## 7. Parameters

`skills/_resources/PARAMETERS.md` defines every named threshold. Skills reference them as `{{name}}` inside the Thresholds table and Analysis Steps. No skill contains a `$` followed by a digit after this work.

| Parameter | Replaces | Default (EUR) | Spend-relative definition |
|---|---|---|---|
| `{{spend_floor}}` | $20, $50 | 50 | max(50, 1 × target CPA) |
| `{{spend_significant}}` | $100 | 100 | max(100, 2 × target CPA) |
| `{{spend_material}}` | $200 | 200 | max(200, 3 × target CPA) |
| `{{spend_high}}` | $500 | 500 | max(500, 5 × target CPA, 5% of 30-day account spend) |
| `{{monthly_spend_significant}}` | $1000/mo | 1000 | max(1000, 10% of 30-day account spend) |
| `{{monthly_spend_large}}` | $5000/mo | 5000 | max(5000, 25% of 30-day account spend) |
| `{{min_clicks}}` | (new) | 100 | minimum clicks before judging a rate (CTR, CVR) |
| `{{min_impressions}}` | (new) | 1000 | minimum impressions before judging CTR or IS |
| `{{min_conversions}}` | (new) | 15 | minimum conversions before comparing CPA/ROAS |
| `{{currency}}` | $ symbol | account currency | always read from `customer.currency_code`; never assumed |

Rules written into PARAMETERS.md and the schema:

- When target CPA is not set, the EUR default applies.
- "30-day account spend" is the sum of `metrics.cost_micros` over the report's date range, converted to currency units.
- Placeholder-value checks ("all conversions valued at $1") become "all conversions valued at exactly 1 `{{currency}}`"; "$0 value" becomes "zero value".
- Rate-based conditions (CTR, CVR, CPA vs average) apply only above `{{min_clicks}}` or `{{min_conversions}}`; below that the skill reports "insufficient sample" as Info, never Critical.
- A client profile (section 8) may override any default.

## 8. Output, provenance, language, client profile

`skills/_resources/OUTPUT_TEMPLATES.md` holds the short and detailed templates in English (other report languages are translated at render time), plus a mandatory report header:

```
## <Skill title> — <Account name>
Account <id> · currency <CUR> · data <date range> · snapshot <YYYY-MM-DD>
Library eppc-ads-skills@1.0.0 · skill <skill-id> (upstream <upstream_skill>@1.8.0) · profile <client slug or "defaults">
```

Every finding line carries the skill id, so a reader can trace it. The report is written in the client's `report_language` (it or en); skill bodies stay in English. The schema's output rules gain: never report the same entity+condition twice across related skills (the more specific skill wins), group by severity, quantify impact in `{{currency}}`.

`skills/_resources/CLIENT_PROFILE.md` is the template the front desk reads from `ads/profile.yaml` in a client repo, or asks for when missing: `slug`, `report_language`, `market` (country list), `currency_override` (normally empty), `target_cpa`, `target_roas`, `monthly_spend`, `brand_terms`, `parameter_overrides`.

## 9. Front desk (`ads/SKILL.md`)

Rewritten for this library. Contents:

- Triggers (English phrasings) and the description line.
- Operating rules: recommend-only, never execute mutations; input is a manual Google Ads UI/Editor export or a `/google-ads:get` export, and `/google-ads:get` is only allowed for a client with a signed DPA covering TrueClicks; never send account data anywhere else; read currency from the account; write in `report_language`; run Consent Mode v2 (075) in every tracking workflow for EEA accounts; cite provenance on every finding; do not double-report across related skills.
- Routing: a table from request type to a workflow preset, each preset a list of skill ids: full audit, waste, search terms, keyword hygiene, creative, budget and bidding, tracking, PMax and Shopping, audience/geo/device, seasonality, compliance, change history, monthly review, launch review. Presets reference the CATALOG and skip `operational` skills unless the user asks for automation.
- Where things are: PARAMETERS, OUTPUT_TEMPLATES, CLIENT_PROFILE, CATALOG, MERGES.
- No reference to `OS/ads-OS/` or to `pending_changes.json`.

## 10. Lint and catalog (`skills/_resources/scripts/lint.py`)

Python 3, standard library only. `python3 skills/_resources/scripts/lint.py` exits non-zero on any error and prints a summary. `--write-catalog` regenerates `skills/CATALOG.md`.

Checks:

1. Frontmatter parses; has `name`, `description`, `allowed-tools`, and `metadata` with `library`, `upstream`, `upstream_skill`, `category`, `kind`, `data_source`, `markets`, `reviewed`.
2. `name` equals the directory name.
3. Body has exactly the five sections in order.
4. No `$` immediately followed by a digit anywhere in the file.
5. No `/google-ads-get` (hyphen form) anywhere.
6. Every `{{param}}` used exists in PARAMETERS.md.
7. `kind`, `data_source`, `markets` values are in their enums; `category` is in the schema table.
8. `upstream_skill` unique across the library; `merged_from` entries are unique, do not exist as directories, and appear in MERGES.md.
9. `related` entries exist as directories.
10. Warn (not fail) when a file exceeds 130 lines.
11. Count check: exactly 137 skill directories.

Catalog columns: number, name, category, kind, data_source, markets, merged_from, line count. Sorted by number.

## 11. README

Sections: what this is and why; provenance and license (MIT, TrueClicks, upstream version, what was changed); library version and changelog; layout; how to use (front desk, invoking one skill, parameters and client profile, output language); governance (recommend-only, DPA rule, EEA note); known gaps and out of scope (section 2 list, the 17 missing numbers, 37 skills that a period-aggregated snapshot cannot feed and therefore need custom GAQL, listed by id).

## 12. Execution and verification

Work proceeds in phases, one commit each: (1) rename + provenance frontmatter + command fix; (2) merges; (3) parameters; (4) output templates, client profile, schema; (5) front desk; (6) lint + catalog + README. Lint must pass at the end of phases 3 through 6; before phase 3 the `$` check is expected to fail and is run with `--allow-dollars`.

Done means: lint passes with zero errors; 137 skill directories; zero `$<digit>` and zero `/google-ads-get` matches; every skill has the metadata block; CATALOG.md and MERGES.md are committed; `ads/SKILL.md` has no `ads-OS` reference; README present.
